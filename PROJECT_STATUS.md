# CS2 Results Bot — статус проекта

Обновлено: 9 августа 2026 года.

Этот файл — краткий контекст для новых задач Codex. Он не должен содержать токены,
пароли, секретные ключи или другие чувствительные данные.

## Цель продукта

- Первый продукт: Telegram-канал «CS2 Tier-1 – результаты матчей».
- Канал: `@cs2_results`.
- Контент: расписание и результаты заметных матчей CS2 без информационного шума.
- Ближайшая продуктовая цель: 1 000 подписчиков.
- Долгосрочная идея: сеть тематических Telegram-каналов.

## Автоматические публикации

- Результаты проверяются каждые 15 минут.
- Утреннее расписание публикуется в 10:00 по Москве.
- Вечерний итог публикуется в 23:00 по Москве.
- Если подходящих матчей нет, пустое сообщение не публикуется.
- Время рассчитывается в `Europe/Moscow`, но подписи «МСК» и «время московское»
  в карточке и подписи не показываются.

## Источники данных

- Основной источник: документированный PandaScore API.
- Используются endpoints прошедших и предстоящих матчей CS2.
- Для матчей сохраняются идентификаторы лиги, серии, турнира, команд и победителя,
  а также признаки переноса и технического результата.
- Tier турнира загружается пакетно, кешируется и пока используется только для
  shadow-диагностики без изменения production-отбора.
- LiquipediaDB реализован как резервный источник, но production fallback сейчас
  отключён до получения и проверки официального доступа.
- HLTV и BO3.gg не используются production-селектором; старые адаптеры оставлены
  только для миграционных тестов и диагностики.
- Источники не смешиваются внутри одной выдачи.

## Отбор матчей

- Результаты: Tier-1 LAN и явно разрешённые Tier-1 онлайн-стадии.
- Расписание: Tier-1 турниры и заметные матчи популярных команд.
- Исключаются qualifiers, showmatch, academy, youth, junior и малозначимые события.
- Для смешанных турниров разрешаются только явно перечисленные стадии.
- Текущий конфиг отбора находится в `tier1_filter.json`.
- Списки турниров, стадий, популярных команд и алиасов меняются конфигом без
  переписывания основной логики.

## Формат Telegram-публикаций

- Карточки квадратные: 1080 × 1080 px.
- Карточки расписания и вечернего итога поддерживают от 1 до 10 матчей.
- Для 1–3 матчей используется одна колонка, для 4–10 — адаптивная сетка.
- Заголовок и дата выровнены по геометрическому центру карточки.
- Верхние голубая и оранжевая линии зеркальны и доходят до одинаковых внешних полей.
- Логотип канала расположен по центру в верхней части карточки.
- Используются официальные логотипы команд из PandaScore.
- Для отсутствующего логотипа используется плейсхолдер с инициалами.
- Тёмные и светлые логотипы получают контрастную подложку.
- На карточке расписания показываются команды, время и полное название турнира.
- В карточках результатов логотипы находятся над названиями команд, а команды
  выровнены к внешним сторонам: левая — влево, правая — вправо.
- Результаты и победитель скрываются Telegram-спойлером.
- В тексте используется минимальное количество эмодзи.
- Источник данных указывается в подписи.

## Надёжность и безопасность

- Токены и ключи хранятся в Yandex Lockbox, а не в репозитории.
- Cloud Function не должна быть публичной.
- Object Storage используется для атомарной дедупликации и delivery claims.
- Матч помечается опубликованным только после успешной доставки.
- Есть защита от повторов при переключении PandaScore ↔ Liquipedia.
- Внешние логотипы принимаются только с разрешённых HTTPS-хостов PandaScore.
- Ограничены тип, размер ответа, разрешение изображения, таймауты и редиректы.
- При ошибке карточки бот возвращается к текстовому сообщению.
- Критические ошибки отправляются администратору Telegram с cooldown.
- Telegram admin chat ID настроен; его значение не следует публиковать в документации.
- `yc CLI` установлен и настроен для read-only проверок без браузера.
- Deploy-скрипт переносит environment variables и ссылки Lockbox из production,
  проверяет candidate через `dry_run` и только затем переключает production-тег.
- Deploy останавливается до создания версии, если таймеры не закреплены на
  `production`, отсутствуют обязательные настройки или Lockbox-привязки.

- Первые автоматические публикации в 10:00, каждые 15 минут и в 23:00.
- Отсутствие пропущенных Tier-1 матчей и ложных срабатываний фильтра.
- Появление объектов `claims/` и `processed/` в Object Storage.
- Доставку технических алертов администратору.
- Корректность карточек в дни с 1, 4 и 10 матчами.
- Сопоставление PandaScore tournament tier с текущим конфигурационным отбором.
- Поведение при временной недоступности PandaScore.
- Расходы и ошибки Yandex Cloud Functions, Object Storage и Logging.

8. Не запускать сеть каналов, пока первый канал не доказал стабильность и спрос.

## Известные ограничения

- PandaScore Fixtures может не предоставлять полную статистику карт и игроков.
- Liquipedia fallback не активен без официального ключа и финальной проверки.
- Классификация Tier-1 зависит от поддерживаемого конфига турниров и стадий.
- PandaScore tournament tier пока диагностический и не меняет production-фильтр.
- Карточка ограничена десятью матчами; при большем количестве нужен отдельный
  продуктовый выбор: несколько карточек или дополнительная фильтрация.
- Пока нет полноценной продуктовой аналитики по источникам подписчиков.

## Экономный процесс работы с Codex

1. Несколько визуальных и продуктовых правок накапливаются локально.
2. До публикации проверяются макеты на 1, 4 и 10 матчей.
3. Промежуточные версии не отправляются в GitHub, Yandex Cloud и Telegram.
4. Полный набор тестов запускается один раз после согласования серии правок.
5. Фраза пользователя «Утверждаю — выкладывай» разрешает единый release-цикл:
   один PR → одна CI-проверка → один deploy → один dry-run → один тестовый пост.
6. Для новой задачи сначала читать этот файл и только затем точечно открывать
   необходимые исходники и документацию.
7. После каждого значимого релиза обновлять дату, commit, количество тестов,
   cloud version, завершённые работы и следующие шаги.
