# Telegram-админка

Админка — отдельная private Cloud Function с handler `cs2bot.admin_handler.handler`.
Она принимает только webhook Telegram через API Gateway и не вызывает jobs публикации.

## Доступ и включение

В production оба флага включены:

```text
TELEGRAM_ADMIN_ENABLED=1
PUBLICATION_CONTROL_ENABLED=1
```

Для подключения нужны `TELEGRAM_ADMIN_USER_ID` одного владельца и
`TELEGRAM_ADMIN_WEBHOOK_SECRET` из Lockbox. `TELEGRAM_ADMIN_CHAT_ID` остаётся
получателем технических алертов и не даёт доступа к меню. Webhook проверяется по
заголовку `X-Telegram-Bot-Api-Secret-Token`; админка отвечает только в личном чате.

## Поведение

`/admin` открывает обзор, каналы, типы постов, журнал и проблемы. Кнопки используют
короткие callback-идентификаторы, поэтому стабильный ID длинного канала не попадает
в callback. Настройка относится к паре «назначение × формат».

В обзоре доступны сегодня, последние 7 календарных дней и текущий месяц — границы
считаются в `Europe/Moscow`. Подтверждённые публикации группируются по назначениям
и форматам, а очередь показывается отдельно на момент открытия: ожидает отправки,
безопасного retry, приостановлена или оставлена на ручной проверке. Журнал
объединяет подтверждённые факты с доступной durable outbox и выводит до 10 строк на
страницу. Экран «Проблемы» показывает удержанные элементы; отсутствие подходящих
матчей проблемой не считается.

Отключение увеличивает поколение очереди. После последующего включения новые
материалы получают новое поколение, а более старые элементы остаются удержанными
для ручной проверки. Админка никогда не повторяет `attempting`, `uncertain` или
`sent` delivery claim.

Журнал подтверждённых доставок не дублирует claims: `attempting` и `uncertain` не
переоткрываются, а старая очередь только классифицируется для ручной проверки.
История до включения версии может быть неполной. Альбом считается одной публикацией,
тестовые выпуски не входят в основные счётчики.

Legacy-итоги турниров без подтверждённого финала остаются удержанными: это не
ошибка доставки и не повод отправлять alert о недоставленных сообщениях.

## Фактическое состояние подключения

4 октября 2026 подключены private функция `cs2results-telegram-admin` и Gateway
`cs2results-telegram-admin`. Gateway использует отдельный service account только
с ролью `functions.functionInvoker` и обращается к тегу `production`; publisher
не стал публичным. Admin production — `d4eoh7cd4dnhhdcpiuur`, основной publisher
— `d4e7f2tjqrkjl9p3la5v`; для обоих сохранены rollback-версии.

Owner ID и webhook secret находятся в отдельном Lockbox secret. Initial policy
`admin/publication-policy-v1.json` записан с revision 1 и пустыми entries: это
сохраняет прежнее разрешение всех пар, но при включённом control-флаге отсутствие
или ошибка policy всё равно блокирует новые внешние отправки. Webhook зарегистрирован
для Gateway `/telegram/admin` с secret token и только для `message` и
`callback_query`.

Пустой запрос и корректно подписанный запрос от чужого user ID получили `403`.
Ожидающий `/admin` владельца обработан за 3,75 с, меню доставлено, а webhook
снова не имеет pending updates и не сообщает ошибок. Admin-function получает
`TELEGRAM_CHAT_ID=@cs2_results`, поэтому каталог содержит Telegram-канал `global`.

## Порядок подключения

1. Собрать `scripts/build_admin_function_zip.sh` и создать private функцию.
2. Дать service account Gateway право invocation только этой функции.
3. Подключить Lockbox references, initial policy и `PUBLICATION_CONTROL_ENABLED=1`.
4. Настроить Gateway на tag `production`, проверить существующий webhook и только
   затем зарегистрировать новый webhook Telegram с secret token.
5. Открыть `/admin` в личном чате владельца и проверить, что публикации не запускались.

Возврат `PUBLICATION_CONTROL_ENABLED` в `0` отключает удержания policy. Это не
является безопасным rollback, если администратор уже поставил форматы на паузу.
