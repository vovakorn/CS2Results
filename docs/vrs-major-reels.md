# VRS Major Reels

Приватная функция `cs2-vrs-major-reels` получает датированные VRS из
LiquipediaDB и по запросу создаёт один из трёх региональных роликов.
Она работает отдельно от основной Python-функции бота и социальных публикаций.

Новый `job=monthly` создаёт один мировой Reel за закрытый месяц; его подпись,
отдельный publisher и месячный timer описаны в [контракте месячных Reels](monthly-vrs-reels.md).

## Использование

Проверить реальный источник без записи и кодирования:

```bash
yc serverless function invoke cs2-vrs-major-reels --tag production \
  --data '{"job":"capture","dry_run":true}'
```

Сохранить полный исходный ответ в приватный архив:

```bash
yc serverless function invoke cs2-vrs-major-reels --tag production \
  --data '{"job":"capture","dry_run":false}'
```

Собрать и сохранить выбранный регион:

```bash
yc serverless function invoke cs2-vrs-major-reels --tag production \
  --data '{"job":"render","region":"americas","dry_run":false}'
```

Другие значения `region`: `europe`, `asia`. Каждый регион — отдельный запрос.
Без `dry_run:false` операция только проверяет данные. Полный рендер тестовой
выборки без сети и Object Storage:

```bash
yc serverless function invoke cs2-vrs-major-reels --tag production \
  --data '{"job":"render","region":"americas","dry_run":true,"render_probe":true}'
```

`render_probe` использует сохранённые публичные наблюдения, а не свежий API.
Для реального источника отдельно проверяется `capture` dry-run. `through`
задаёт включительную дату конца истории, по умолчанию — текущую дату UTC.
Будущие даты отклоняются. Начало кампании — 22 июня 2026. После подтверждения
объявления участников его дату передают в `through`: дата рейтинга отбора
не выдаётся за дату объявления.

Ответ `capture` содержит `sourceKey`. Передайте его в `source_key` при `render`,
чтобы повторно использовать ровно сохранённый ответ без нового запроса к API.
Разрешены только ключи исходников текущей кампании.

## Правила данных и рендера

Читаются полные списки `vrs_ranking_live` с лимитами объёма ответа и пагинации.
Квоты выбора — 18 / 9 / 5 плюс два ближайших преследователя на последней дате;
берётся объединение команд внутри квоты по всем сохранённым датам. Это история
производного регионального рейтинга, не расчёт eligibility и принятия приглашений.
Методика: [README компонента](../video/vrs-major-race/README.md).

Шаблоны команд и переходы брендов проверены явно. Неизвестный шаблон,
неподтверждённый переход, неполный источник, неоднозначные места или более
24 историй в регионе останавливают сборку. Команды не отбрасываются молча.
Пропуски остаются пропусками; очки не подменяются другим источником.

16 октября API повторно вернул 15 дат от 22 июня до 5 октября: подтверждены
те же 646 наблюдений, Europe 23, Americas 12, Asia 9. Дата запроса не становится
датой последнего рейтинга.

1080 × 1920, 60 fps, 1 944 кадра, 32,4 секунды. Используются общий
`paint-frame.mjs`, таймлайн, CPU Canvas / Skia и FFmpeg. Для Linux включён
метрически совместимый Arimo Bold вместо системного Arial, с лицензией OFL.
Оригинальная оркестровая тема заранее записана в WAV и проверяется по SHA-256;
Swift и звуковой банк macOS для production не нужны. Для 2–40 дат длительность
переходов подстраивается к фиксированному музыкальному финалу. Перед сохранением
обязательны полное декодирование MP4 и проверка пикового уровня звука.

## Хранение и доступ

Приватный state bucket, префикс `vrs-major/cologne-singapore-2026/`. Исходники
и результаты адресуются по контрольным суммам и записываются с `If-None-Match: *`.
Конфликтующий объект не перезаписывается. Пересчитанный ответ API сохраняется
отдельно; архив не доказывает неизменность первоначальной публикации рейтинга.

`render` возвращает ключи MP4, PNG, данных, подписи и манифеста. Это приватные
объекты; для скачивания нужен доступ к bucket. Функция не получает Telegram/Meta
credentials и не вызывает социальные API. Публикация и расписание выпусков
в этот релиз не входят.

Runtime `nodejs22`, 1024 MB, 600 s, concurrency 1. Только закреплённые Lockbox
references `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `LIQUIPEDIA_API_KEY`
и настройка `OBJECT_STORAGE_BUCKET`. Анонимный вызов запрещён. Новых таймеров нет.

## Сборка и релиз

```bash
cd video/vrs-major-race/cloud
pnpm install --frozen-lockfile --ignore-scripts
node --test ../timeline.test.mjs ../data.test.mjs handler.test.mjs
cd ../../..
python3 scripts/build_vrs_major_function.py
```

`dist/vrs-major-function.zip` содержит только VRS-обработчик, библиотеки,
Linux x64 Skia/FFmpeg, проверочные данные и ассеты. Версия и SHA-256 FFmpeg
закреплены в `assets/vendor.json`. Архив основной функции бота не меняется.
CI на Linux собирает архив и полностью кодирует/декодирует Americas через
упакованный обработчик.

`scripts/deploy_vrs_major_function.py check` — read-only preflight. `candidate`
требует чистый Git, один раз собирает архив, использует существующий приватный
package bucket, создаёт отдельную функцию при отсутствии, проверяет полный
рендер и реальный источник. Копируются только три закреплённые ссылки Lockbox,
не значения секретов. `promote <manifest>` требует `YC_PROMOTE_APPROVED=1`,
проверяет исходную версию бота, таймеры и отсутствие анонимного доступа.
При неуспехе smoke тег откатывается; при первом релизе тег удаляется.
Манифесты — `dist/vrs-releases/`. Порядок: PR, CI, merge, candidate, promote.
