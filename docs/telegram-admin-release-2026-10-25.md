## Изменение

При сбое `answerCallbackQuery` подтверждение кнопки больше не выполняется
повторно перед обновлением экрана. Истёкшее подтверждение не блокирует сам
переход. Точный ответ Telegram `message is not modified` при редактировании
уже показанного экрана считается успешным, остальные отказы остаются ошибками.
Автоматических повторов неоднозначной отправки нет.

Объекты журнала читаются максимум четырьмя запросами одновременно, включая
чтение тел в рабочих потоках. Страницы и ключи дедуплицируются; некорректная
пагинация завершается явной ошибкой. Полнота исторических данных и ограничение
чтения 500 записей этим релизом не исправляются. Сетевой сбой входящего webhook
не объявляется устранённым на основании локальных тестов.

## Облачный preflight и границы

Admin private function: `d4erm6ek4ph9qegng4gb`, production до релиза —
`d4eo6o0llg2ap95fphit`. Runtime `python312`, handler
`cs2bot.admin_handler.handler`, 256 MiB, 30 с, concurrency 4. Переносятся
только прежние environment и шесть закреплённых Lockbox references;
значения секретов для сборки/переноса не читаются.

Gateway `d5deuua19e37pj92jr82` вызывает admin tag `production`, не `$latest`.
Функция не имеет anonymous bindings. Девять timer triggers сохранены, все
вызывают закреплённый `production`; радар PAUSED. Основной publisher до релиза
admin: `d4e0ko5n3dfonjcem4f4`; он не переключается.

Candidate создаётся с отдельным тегом `candidate-admin`. Вызов пустого события
должен получить **403** от handler: это ожидаемая проверка закрытого доступа и
импорта, без Telegram-сообщений, jobs, чтения журнала или изменения policy.
Для admin-handler scheduler dry-run не используется. После smoke обязательно
прочитать startup-логи: ошибка чтения сохраняется как `log_read_failed` и
останавливает promote. Прежние разрешения на пропуск логов других релизов
к admin-кандидату не применяются.

Предыдущий admin production закрепляется под `rollback` перед переключением.
После promote проверяются точный тег, неизменность конфигурации, IAM, Gateway
и таймеров, fail-closed smoke и доступность меню владельцу. Нельзя отключать
`PUBLICATION_CONTROL_ENABLED` для отката: это отменило бы действующие паузы.
Снимки и release manifest хранятся локально в `dist/admin-release/`.
