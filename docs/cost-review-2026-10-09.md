## Локальные изменения

- `main.py`: retry читает result outbox один раз. При пустой очереди выполняет
  worker сегодняшнего Reel и, при достаточном остатке времени, очередь digest;
  возвращается до подготовки платформ
  результатов и media health. Сбой чтения очереди или Reel возвращает 502,
  не сообщение об отсутствии работы. Пятиминутный timer сохранён.
- `storage.py`: до четырёх параллельных чтений объектов; все страницы читаются
  до глобальной сортировки и применения лимита. Ошибка чтения/пагинации не
  считается пустой очередью. Исчезнувший после параллельной доставки объект
  пропускается. Повреждённые элементы логируются и не мешают валидным; очередь
  только из повреждённых элементов возвращает ошибку.
- `match_fetcher.py`: одна загрузка Liquipedia для shadow и final cards.
  Диагностический timeout не отменяет загрузку, необходимую для финалов.
  Все проверки полной таблицы, победителя, последнего конкурентного матча,
  bridge alias и десятиминутное ожидание сохранены.
- Shadow: не больше одной попытки сравнения в UTC-час благодаря атомарному
  PUT `diagnostics/liquipedia-shadow/YYYY-MM-DDTHH.json`. Маркер содержит только
  claimed_at, сохраняется и при сбое сравнения. Если запись маркера недоступна,
  shadow пропускается, а финалы продолжают проверяться. Dry-run не пишет маркер
  и выполняет диагностику без ограничения. Отдельный timer не добавлен.
- Поведение Reel sent/uncertain/held сохранено и проверено тестами: обращения
  к Meta и повторной публикации в этих состояниях нет. Состояние сегодняшнего
  Reel читается один раз за retry.
- После обновления базы на PR #151 сохранён новый digest worker: пустая очередь
  результатов не отключает повтор подготовки итога дня. Исходная дата,
  owner generations и ограничение времени/попыток остаются прежними; ошибка
  Reel не отменяет проверку ожидающего digest.

Десятиминутный timer не выбран: сохранена текущая скорость повторной доставки.
Почасовое сравнение сокращает диагностику с 96 до максимум 24 попыток в сутки;
после объединения выборок это не дополнительные 75% экономии HTTP-запросов.

## Проверки и границы

262 целевых теста прошли. 12 октября перед согласованным релизом полный набор
прошёл: 868 тестов за 224,35 с. Audit зависимостей не обнаружил известных
уязвимостей; компиляция исходников, проверка diff и базовая локальная сборка
успешны. Публикация кода выполняется отдельным согласованным release-циклом.
После объединения с PR #151 прошли 297 целевых тестов retry, digest, Reel,
storage и источников, а также 903 полных локальных теста за 224,42 с.
Итоговый CI Python 3.11/3.12 успешен; production-архив с Xray собран локально.
Ветка: `codex/cost-reduction-2026-10-09`. Подтверждена сохранность всех 64
незавершённых файлов исходного checkout по SHA-256.

Целевые проверки покрывают общую загрузку, независимость финалов от shadow,
timeout/fail-open, dry-run без записей, часовое резервирование, предел четырёх
чтений, многостраничную сортировку, пустую/повреждённую очередь, ожидание Reel и
терминальные claims. Документация обновлена в изолированном worktree от
origin/main; незавершённые файлы исходного checkout сохранены.

Expiration диагностических маркеров через 30 дней рекомендовано в lifecycle
документе, но cloud lifecycle этой задачей не менялся. Рублёвую экономию
вычислений предстоит измерить по billing после накопления данных production.

слит в main 12 октября в 10:25:58 МСК, Git `e2471a30a3e10e1114a221408a96066f444c8d8b`.
Он содержит оптимизации, их интеграцию с digest worker из PR #151 и документацию;
итоговые проверки приведены выше.
Read-only gate облака не пройден: сначала таймаут, затем ответ `function not
found`, а повторные списки функций и таймеров вернули `Unavailable`. Эти ответы
не доказывают удаление ресурсов. [Официальный инцидент Yandex Cloud](https://status.yandex.cloud/ru/incidents/2136)
на момент проверки открыт и включает Cloud Functions; платформа работает в
ограниченном режиме. Candidate, promote, смена таймеров и публикации не
выполнялись. На 12 октября следующим шагом оставались повторный `check` и
candidate → smoke → promote с сохранением rollback; фактическая выкладка
16 октября подтверждена ниже.
