# Object Storage Lifecycle

Object Storage используется для состояния дедупликации и кеша проверенных PNG-логотипов. Raw HTML, raw API responses и пользовательские секреты туда не пишутся.

## Ключи

Для публикаций в Telegram используется per-channel ключ:

```text
processed/{channel_id}_match_v1_{fingerprint}.json
```

Пример:

```text
processed/global_match_v1_5528f9748a200b85a2dfdc2b.json
```

Перед отправкой создаётся атомарный lease:

```text
claims/{channel_id}_match_v1_{fingerprint}.json
```

До подтверждённой отправки нормализованный матч хранится в durable outbox:

```text
outbox/results/{channel_id}_match_v1_{fingerprint}.json
```

После processed marker outbox item удаляется. Короткое состояние адаптивного
text-only режима хранится в `delivery-health/telegram-media.json`.

Старые source-specific ключи продолжают читаться для безопасной миграции. Поле
`id` в `CHANNELS_JSON` должно быть стабильным и уникальным. Claim начинается в
`sending`; непосредственно перед внешним запросом становится `attempting`.
Подтверждение переводит его в `sent`, неоднозначный ответ — в `uncertain`, а
определённый отказ — в `released`. Состояния `attempting`, `uncertain` и `sent`
не перехватываются после истечения обычного lease; только `sending` можно
автоматически перехватить, а `released` — сразу использовать заново.

Проверенные PNG-логотипы PandaScore сохраняются под непрозрачным ключом, зависящим
от URL. При смене URL создаётся новая версия; сбой чтения или записи кеша не
препятствует публикации:

```text
media/logos/{sha256-url}.png
```

## IAM

Сервисному аккаунту Cloud Function нужны минимальные права на bucket:

- `head_object` / чтение метаданных;
- `get_object` и `list_objects_v2` / чтение очереди;
- `put_object` / запись объекта, включая conditional `If-None-Match` и `If-Match`;
- `delete_object` / удаление доставленных outbox items и сброс media health.

Ключи доступа не должны храниться в коде. Используйте только переменные окружения:

```text
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
OBJECT_STORAGE_BUCKET
OBJECT_STORAGE_ENDPOINT
```

## Lifecycle policy

Рекомендуется удалять `processed/*` через 180-365 дней, а аварийно оставшиеся
`outbox/results/*` через 30 дней. Не применяйте безусловное lifecycle-правило ко
всему prefix `claims/*`: оно удалит `attempting` или `uncertain` и снова откроет
возможность автоматической публикации. Такие claims удаляются только после
ручной сверки с платформой или будущим state-aware cleanup-процессом.
Для `media/logos/*` подходит срок от 365 дней: смена логотипа создаёт новый ключ,
а старые версии можно удалять lifecycle-правилом.

Для MVP это безопасно, потому что:

- матч не должен повторно публиковаться спустя месяцы;
- объекты маленькие, но со временем их станет много;
- стоимость будет низкой, но Object Storage остаётся платным ресурсом.

Практическая рекомендация:

- development bucket: 30-90 дней;
- production bucket: 180-365 дней;
- prefix: `processed/`.

## Ошибки и повторы

Claim закрывает гонку между параллельными invocation. Перед внешним запросом
состояние `attempting` делает доставку fail-closed: даже если платформа приняла
публикацию, а запись `sent` не удалась, следующий invocation её не повторит.
После подтверждения `sent` записывается до processed marker; временная ошибка
записи повторяется до трёх раз. Если процесс прервётся после записи `sent`,
следующий запуск создаст marker без повторной публикации.

Для результата Telegram PNG делает до двух попыток при безопасном
`ConnectTimeout`, после чего текст отправляется в том же invocation. Если
соединение не установилось и для текста, claim освобождается, а outbox остаётся
для следующего разнесённого повтора. При остальных сетевых ошибках, HTTP 5xx или
невалидном ответе исход неизвестен: claim становится `uncertain`, result outbox
удаляется, автоматический повтор и текстовый fallback запрещены.

Если один канал успешно отправлен, а следующий канал упал, уже успешный канал остаётся помеченным и не должен получить дубль при следующей попытке.

Payload processed-объекта содержит `start_date` и `end_date`, если источник их отдал. Это помогает ручной диагностике дублей и старых публикаций.
