# Safe zone вертикальных Reels

Выпущено 25 октября 2026: PR #164, согласованные версии main/VRS/monthly.
Полный CI, candidate render/source и production dry-run прошли. Startup-логи
недоступны и остаются непроверенными по разовому разрешению пользователя.
[Точные версии и результаты](reels-safe-zone-release-2026-10-25.md).

Для кадра **1080 × 1920** главный текст, знаки команд, данные и CTA
располагаются в **x=80…920, y=250…1570**: 840 × 1320 px.
Это согласованные рабочие отступы: слева 80, справа 160, сверху 250,
снизу 350 px. Они не являются универсальной гарантией для любой версии
интерфейса Instagram. Фон, рамки и декоративные watermark могут выходить
за область. Демо-плашка вне неё предназначена только для локальных превью.

Единый контракт: `data/reel-safe-zone.json`, версия `instagram-safe-v1`.
Python читает его через `cs2bot/reel_layout.py`; Canvas — через
`video/vrs-major-race/layout.mjs`. Центр полезной области по X — 500,
поэтому контент слегка смещён влево относительно центра всего кадра.

## Расписание

- Знак канала, включая внешний ободок, находится ниже верхней границы.
- Сетка участников и список из четырёх матчей занимают ширину до 808 px;
  карточки высотой 210 px разделены промежутком 16 px.
- Источник, номер страницы, нижний призыв и прогресс находятся выше `y=1570`.
- Названия могут занимать две строки; для длинных имён минимальный кегль
  уменьшен с 36 до 30 px. Пределы 1–20 матчей, порядок, длительности и звук
  сохранены. Область анимированного появления соответствует новым карточкам.

## VRS и обложка

Шапка, шкала, график, таблица и даты перенесены внутрь safe zone.
Реальные мировые места, состав выборки, значения, даты и логика смены
составов не изменены. Общее оформление используется мировым и тремя
региональными вариантами.

Первые 1,2 s VRS — отдельная обложка: знак проекта, крупный центральный
заголовок, месяц/год или регион. Далее переход 0,4 s к графику; движение
рейтинга начинается на прежних 1,8 s. Длительность остаётся 32,4 s.
Заголовок обложки сохраняется при центральных кропах 3:4, 4:5 и 1:1.
Это проверочные кропы, а не утверждение о текущей сетке конкретного аккаунта.

Общий Instagram publisher явно задаёт `thumb_offset=500` (миллисекунды)
при создании новых Reel-контейнеров. В расписании выбран сразу видимый
первый экран, в VRS — статичная обложка. Выбор кадра описан в
[официальном примере Meta](https://github.com/fbsamples/reels_publishing_apis/blob/main/insta_reels_publishing_api_sample/README.md#custom-thumbnail-support-thumb_offset).
Отдельная публичная картинка для обложки не загружается.

## Совместимость и выпуск

Новые VRS render receipts содержат `layoutVersion=instagram-safe-v1`
и `coverOffsetMs=500`. Месячный publisher требует оба значения до загрузки
публичного MP4 и создания контейнера. Старый prepared receipt без них
останавливает подготовку с ошибкой; он не заменяется автоматически.
Уже сохранённые pending-контейнеры продолжают прежний защищённый путь:
они не пересоздаются и их обложки не меняются.

Для выпуска требуются согласованные версии основного бота, отдельного
Node-рендерера VRS и месячного Python publisher. Сначала рендерер,
затем publishers; перед включением проверить prepared/pending состояния.
Старый receipt без нового контракта требует ручной проверки до разрешения
публикации. Состояние доставки, claims и markers вручную здесь не менялись.
Оба Python ZIP включают JSON-контракт; Node bundle встраивает его.

## Проверка

```bash
python -m pytest tests/test_schedule_reels.py tests/test_reel_intro.py tests/test_reel_safe_zone.py tests/test_instagram_publish.py tests/test_monthly_vrs_reels.py tests/test_reel_delivery.py tests/test_main_schedule_reel.py -q
cd video/vrs-major-race/cloud
node --test ../timeline.test.mjs ../data.test.mjs ../monthly.test.mjs handler.test.mjs safe-zone.test.mjs
```

Проверяются реальные текстовые bounding boxes и области логотипов:
1/4/10/20 матчей, длинные/кириллические названия, отсутствующие и контрастные
логотипы, смешанные турниры; VRS world/Europe/Americas/Asia и кропы обложки.
Проверка decoded pixels использует новую геометрию и анализирует график
после намеренного перехода от обложки. На телефоне после выпуска отдельно
проверить реальную обложку и перекрытия UI.
