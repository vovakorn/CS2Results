## Как не повторять расхождение

- Основная папка содержит чистый `main`; одна задача выполняется в одной короткой
  ветке/worktree от свежего `origin/main` после fetch.
- После merge ответственный обновляет чистую основную папку fast-forward и
  проверяет `HEAD == origin/main`. GitHub CI не обновляет локальную папку.
- На GitHub включены обязательный PR и три существующие проверки от GitHub Actions:
  `pytest (3.11)`, `pytest (3.12)`, `vrs_reels`; база должна быть актуальной.
  Правила действуют и для администратора, force-push и удаление main запрещены.
  Обязательный второй человек не требуется (0 human approvals).
  [Прочитанная конфигурация](reviews/2026-10-29/main-protection.json).
- Послерелизная документация также проходит короткий PR. Само описание процесса
  не разрешает новые PR, merge, deploy или внешние публикации вне указаний пользователя.
- `PROJECT_CONTEXT.md` сокращён с 578 до 38 строк. Полный прежний текст сохранён
  в [PROJECT_HISTORY.md](../PROJECT_HISTORY.md), он не загружается при обычном старте.
  Это уменьшает ненужное чтение контекста; точный финансовый эффект не измерялся.

Новые сервисы, постоянные develop/release-ветки, hooks и автоматическое разрешение
конфликтов не добавлялись. [Workflow](local-workflow.md),
[production-протокол](audit-release-2026-10-29.md).
