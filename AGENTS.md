# Инструкции для Codex

## Начало задачи

- Сначала прочитай `PROJECT_CONTEXT.md` и проверь `git status`.
- Не загружай всю документацию заранее. Открывай только нужный источник:
  - продуктовые правила — `docs/requirements.md`;
  - устройство системы или изменения между модулями — `docs/architecture.md`;
  - модели данных и дедупликация — `docs/data-contract.md`;
  - запуск и конфигурация — `README.md`;
  - production, релиз или инфраструктура — `PROJECT_STATUS.md` и
    `docs/yandex-cloud-deploy.md`;
  - будущие задачи — `BACKLOG.md`.
- Не изменяй и не добавляй в коммиты чужие или незавершённые изменения.
- Никогда не добавляй в репозиторий токены, пароли, API-ключи и содержимое
  секретов.

## Экономный режим

- Пиши короткие отчёты: результат, существенная проблема и следующий необходимый
  шаг.
- Не пересказывай документы и не выводи длинные логи или большие фрагменты файлов.
- Сначала используй поиск и точечное чтение, затем открывай только релевантные
  участки кода.
- Объединяй связанные изменения в одну локальную итерацию.
- Во время итерации запускай точечные тесты; полный набор — один раз перед
  согласованным релизом.
- Для изменений только документации проверь ссылки, форматирование и итоговый diff;
  тесты кода не нужны.
- Не обращайся к GitHub, Yandex Cloud и Telegram для каждой мелкой правки.

## Локальная работа и публикация

- По умолчанию изменения остаются локальными.
- Без явного разрешения пользователя не создавай PR, не сливай ветки, не выполняй
  deploy и не отправляй сообщения в Telegram.
- Фраза «Утверждаю — выкладывай» разрешает один общий release-цикл для уже
  согласованных изменений: итоговый diff → полный набор тестов → один PR → CI →
  merge → один deploy → dry-run → один тестовый пост, если он нужен.
- Если пользователь просит только GitHub, облако или Telegram, выполняй только
  названную часть.
- После значимого релиза обнови `PROJECT_CONTEXT.md`, `PROJECT_STATUS.md` и
  `BACKLOG.md`, если фактическое состояние изменилось.

## Проверки

- Точечные тесты карточек: `python -m pytest tests/test_media_cards.py -q`.
- Полная проверка: `python -m pytest -q`.
- Сборка функции: `scripts/build_function_zip.sh`.
- Перед production-деплоем выполни проверку из
  `docs/yandex-cloud-deploy.md`; таймеры должны вызывать тег `production`, а не
  `$latest`.
- Для визуальных изменений проверь варианты на 1, 4 и 10 матчей, длинные названия,
  отсутствующие и контрастные логотипы, отсутствие перекрытий и формат 1080 × 1080.
