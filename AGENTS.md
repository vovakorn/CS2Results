# Инструкции для Codex

## Контекст проекта

- Перед началом работы полностью прочитай `PROJECT_STATUS.md`.
- `PROJECT_STATUS.md` содержит актуальное состояние продукта, инфраструктуры,
  принятые решения, ограничения и следующие шаги.
- Открывай `README.md`, документацию и исходники только по мере необходимости.
- В начале задачи проверь `git status` и не изменяй, не удаляй и не добавляй в
  коммиты чужие или незавершённые изменения.
- Никогда не добавляй в репозиторий токены, пароли, API-ключи и содержимое секретов.

## Экономный режим работы

- Пиши короткие отчёты: результат, найденные проблемы и следующий необходимый шаг.
- Не повторяй историю проекта, уже зафиксированную в `PROJECT_STATUS.md`.
- Не выводи длинные логи, полные снимки веб-страниц и большие фрагменты файлов,
  если для решения достаточно краткого результата.
- Объединяй связанные изменения в одну локальную итерацию.
- Для визуальных изменений показывай одним набором варианты на 1, 4 и 10 матчей.
- Во время итераций запускай только точечные тесты. Полный набор запускай один раз
  после согласования серии изменений.
- Для изменений только в документации не запускай тесты кода; достаточно проверить
  форматирование и diff.
- Не открывай GitHub, Yandex Cloud и Telegram для каждой мелкой правки.

## Локальная работа и публикация

- По умолчанию все изменения остаются локальными.
- До явного утверждения пользователя не создавай PR, не сливай ветки, не выполняй
  deploy и не отправляй тестовые сообщения в Telegram.
- Фраза пользователя «Утверждаю — выкладывай» разрешает один общий release-цикл
  для согласованного набора изменений:
  1. проверить итоговый diff;
  2. запустить полный набор тестов один раз;
  3. создать один PR и дождаться CI;
  4. слить PR;
  5. выполнить один deploy в Yandex Cloud;
  6. выполнить один dry-run;
  7. отправить один тестовый пост, если он нужен для проверки результата.
- Если пользователь отдельно просит только GitHub, облако или Telegram, выполняй
  только явно названную часть и не расширяй действие на остальные системы.
- После значимого релиза обновляй `PROJECT_STATUS.md` фактическим состоянием.

## Проверка карточек

- Карточки расписания должны корректно работать для 1–10 матчей.
- Перед релизом визуально проверяй компоновку на 1, 4 и 10 матчей.
- Проверяй длинные названия команд, отсутствующие, тёмные и светлые логотипы.
- Не допускай перекрытия логотипов, названий команд, времени и турнира.
- Сохраняй квадратный формат 1080 × 1080 px и текущую визуальную систему канала.

## Ключевые команды

- Точечные тесты карточек: `python -m pytest tests/test_media_cards.py -q`.
- Полная проверка: `python -m pytest -q`.
- Сборка функции: `scripts/build_function_zip.sh`.
- Подробности развёртывания: `docs/yandex-cloud-deploy.md`.
